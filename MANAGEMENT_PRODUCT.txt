================================================================================
 1. GAMBARAN UMUM (OVERVIEW)
================================================================================

Module 02 membangun Master Data Produk (SKU) untuk sistem POS RetailControl.
Komponen yang diimplementasikan:

  - Tabel DB        : brands, categories, uoms, items, item_barcodes,
                      price_lists, price_list_items, attribute_definitions,
                      category_attribute_sets
  - RBAC            : 20 permission baru (items/brands/categories/uoms)
  - Controller      : BrandController, CategoryController, UomController,
                      ItemController (CRUD + deactivate + import)
  - Policy          : BrandPolicy, CategoryPolicy, UomPolicy, ItemPolicy
  - Service         : ExcelImportService (11 sheet handler)
  - Artisan Command : ImportProductsCommand (php artisan products:import {path?})
  - Audit Trail     : Auditable trait aktif di semua model master data
  - Seeder          : UomSeeder, CategorySeeder, BrandSeeder,
                      AttributeDefinitionSeeder

Prinsip desain:
  - Single Source of Truth: master produk terpusat, semua cabang mengacu ke
    katalog yang sama.
  - Auditability: perubahan master produk tercatat otomatis (Auditable trait).
  - Modular & non over-engineered: cukup untuk operasi toko material.
  - SKU-first: unit transaksi adalah SKU/Item.
  - Atribut dinamis terkontrol: attributes_json per kategori, terdefinisi di
    attribute_definitions dan dihubungkan via category_attribute_sets.

TEMUAN POLA UMUM
1) Struktur sheet tidak seragam (kolom berbeda per brand/kelompok barang).
2) Ada baris metadata sebelum header tabel (JENIS BARANG/MERK, distributor/sales, tanggal, dll).
3) Harga & diskon tidak konsisten formatnya:
   - Numeric murni (contoh RUCIKA/HCL/MASPION).
   - String berformat rupiah (contoh RUCIKA FITTING: 'Rp. 14.100,-').
   - Diskon bertingkat (DISC 1-3) berupa desimal (0.15 = 15%).
   - Diskon nominal (contoh MU: DISC=2000).
   - Ada hasil harga final/netto sudah dihitung (kolom HARGA/NETTO).
4) Ada konsep kemasan/pack yang penting untuk receiving/purchasing:
   - ISI/BOX (RUCIKA FITTING), Pack (FITTING MASPION), M/ROLL (MILLIARD), KEMASAN (NO DROP).
5) Ada sheet berbentuk 'matrix' (EXTRANA): tipe kabel menjadi kolom (NYM, NYY, dst). Ini harus diubah (pivot) menjadi SKU per tipe.
6) Banyak sheet mencantumkan catatan 'harga sudah PPN' atau 'PPN 11%'. Artinya price list kemungkinan sudah termasuk pajak (perlu flag).

DETAIL PER SHEET (YANG PERLU DIPERHATIKAN SAAT IMPORT)
1) RUCIKA (sheet 'RUCIKA ')
   - Header di baris 8: PRODUK, JENIS, SPESIFIKASI, mm, inch, OD(mm), HARGA, DISC1-3, HARGA(final).
   - DISC 1-3 berbentuk desimal (0.15=15%, 0.07=7%, 0.04=4%).
   - Ada kolom HARGA final (sudah dihitung).
2) RUCIKA FITTING
   - Header di baris 11: PRODUK, JENIS, MM, inch, ISI/BOX, HARGA/PCS, DISC1-3.
   - HARGA/PCS kadang string 'Rp....' -> harus dibersihkan ke numeric.
   - ISI/BOX penting untuk konversi purchase unit (box) ke base unit (pcs).
3) HCL
   - Header di baris 10: No, Type, Jenis, Outlet, Power, Harga Lama, Harga Baru, Disc->TEMPO, Disc->TUNAI.
   - Ini mengindikasikan 2 'price tier': tempo vs tunai (bukan atribut produk).
4) MASPION
   - Header di baris 8: PRODUK, TYPE, UKURAN, BRUTO, NETTO.
   - Sudah ada netto, sehingga untuk pricing awal cukup ambil NETTO.
5) FITTING MASPION
   - Header di baris 6: PRODUK, Jenis, Class, Ukuran, Pack, Bruto, Harga.
   - Pack = qty/box (atau qty/pack), Harga tampak sebagai harga setelah diskon (net).
6) PIPA TRILLIUN
   - Header di baris 6: PRODUK, TYPE, UKURAN, BRUTO, NETTO, DISC1, DISC2, HARGA(final).
   - Ada netto dan final; final kemungkinan adalah setelah disc1+disc2 dari netto.
7) EXTRANA
   - Header di baris 6: PRODUK, JENIS, Ukuran, SATUAN, lalu kolom tipe kabel (NYM, NYY, NYMHY, ...).
   - KET: Harga rupiah/meter. Artinya harga per meter (base_uom=meter).
   - Wajib pivot: setiap kolom tipe kabel yang berisi harga -> menjadi baris SKU dengan attribute cable_type.
8) MILLIARD
   - Header di baris 9: PRODUK, JENIS, DIAMETER(INCH), M/ROLL(m), Harga/roll, DISC1-3, HARGA(final).
   - Ada trailing space pada PRODUK (contoh 'SEAGULL '), harus trim.
9) MU
   - Header di baris 8: MERK, PRODUK, JENIS, HARGA, DISC, NETTO.
   - DISC adalah nominal (contoh 2000), bukan persen.
10) NO DROP
   - Header di baris 8: BRANDS, ITEM, KEMASAN, PRICELIST, NETTO.
   - KEMASAN seperti '1 Kg', '4 Kg', '20 Kg' -> perlu distandarkan (pack_size + unit).
11) POWER PRALON
   - Header di baris 8: Produk, TIPE, MODEL, Inch, mm, HARGA, DISC1->NETT 7,5%, DISC2->NETT 18%.
   - Ada 2 level nett (7.5% dan 18%). Ini bisa diperlakukan sebagai price tier atau promo/level customer.

RISIKO KUALITAS DATA DARI EXCEL (DAN SOLUSI)
- Harga format string: lakukan parse 'Rp', '.', ',', ',-' menjadi integer.
- Inch/MM campur format (1, 1/2, '1 1/4', 5/8"): distandarkan ke string canonical (lihat aturan naming).
- Nilai kosong: beberapa kolom bisa kosong (harga tertentu tidak tersedia). Pada import, baris/variant tanpa harga bisa ditandai 'inactive' atau 'price missing'.
- Diskon bertingkat: jika sudah ada HARGA final/netto, gunakan final sebagai price aktif dan simpan disc breakdown untuk audit.


==========================================================================================
B. RANCANGAN MASTER DATA PRODUK (SKU)
==========================================================================================
B1. KONSEP UTAMA
1) SKU / ITEM
   - 1 SKU = 1 barang yang dijual (dipilih di POS, dicatat stok, masuk DO, masuk PO, dll).
   - Contoh: 'PIPA PVC RUCIKA AW 25mm 4M' adalah 1 SKU.
   - Contoh: 'KABEL EXTRANA 2x1,5 NYM' dan 'KABEL EXTRANA 2x1,5 NYY' adalah 2 SKU berbeda.
2) PRODUCT FAMILY (OPSIONAL)
   - Untuk grouping display saja (mis. keluarga kabel EXTRANA ukuran 2x1,5).
   - Tidak wajib untuk MVP, karena semua operasi bisa cukup dengan SKU.

B2. STRUKTUR FIELD: INTI vs DINAMIS
1) Field inti (wajib, stabil untuk semua jenis barang)
   - sku_code (unik)
   - name (nama tampil di POS)
   - brand_id
   - category_id
   - base_uom_id (satuan jual / satuan stok)
   - pack_qty (konversi dari kemasan purchase ke base_uom; default 1)
   - is_active
   - barcode (opsional; bisa banyak via tabel terpisah jika dibutuhkan)
2) Atribut dinamis (berbeda antar kategori)
   - disimpan di kolom JSON: attributes_json
   - contoh key: diameter_mm, diameter_inch, od_mm, spec, class, model, outlet, power_watt, cable_type, size_mm2, length_per_roll_m, pack_size_kg, dll.

B3. 3 KOLOM CADANGAN
1) attributes_json  : atribut teknis dinamis per kategori (dipakai sekarang).
2) custom_fields_json: tempat data tambahan di masa depan (barcode tambahan, lokasi rak, min_stock, foto_url, supplier_sku, dll).
3) raw_source_json  : simpan jejak baris sumber import (sheet_name, row_number, nilai kolom original) untuk audit & re-import.

B4. DATABASE SCHEMA (TABEL LENGKAP)
Catatan: desain ini sengaja minimal agar tidak over-engineered, namun tetap rapi dan siap berkembang.

B5. PRICING (DIPISAHKAN DARI MASTER PRODUK, TAPI DIIMPORT UNTUK HARGA AWAL)
Rationale: Excel adalah price list; namun arsitektur sistem memisahkan Master Data vs Pricing Management.

==========================================================================================
C. STRATEGI IMPORT & NORMALISASI DARI EXCEL
==========================================================================================
C1. TARGET HASIL IMPORT
Output import harus menghasilkan:
- Daftar SKU (items) lengkap, unik, siap dipakai POS/search/barcode (jika ada).
- Pricing awal tersimpan di price list (price_list_items).
- raw_source_json menyimpan jejak sumber per SKU.

C2. ATURAN UMUM NORMALISASI
1) Trim & bersihkan string
   - strip spasi depan/belakang (contoh 'SEAGULL ' -> 'SEAGULL').
   - normalisasi huruf besar/kecil (gunakan Title Case atau Upper Case konsisten).
2) Parse harga rupiah
   - buang 'Rp', '.', ',', ',-', spasi -> angka integer.
3) Diskon
   - jika kolom DISC berupa 0.xx -> treat sebagai persen.
   - jika DISC > 1 dan tipe nominal (contoh MU) -> treat sebagai potongan rupiah.
4) Standarisasi inch
   - simpan sebagai string canonical, contoh: '1/2', '3/4', '1', '1 1/4', '5/8"'.
   - untuk SKU code, gunakan format tanpa spasi.
5) Konversi kemasan
   - ISI/BOX, Pack -> simpan pack_qty (qty base_uom per box).
   - M/ROLL -> simpan length_per_roll_m (atribut).
   - KEMASAN '4 Kg' -> pack_size=4, pack_size_unit='Kg'.
6) Harga sudah PPN
   - default tax_included=true untuk semua item hasil import.

C3. ATURAN PEMBUATAN SKU (SKU CODE & NAMA TAMPIL)
Format sku_code: <BRAND_CODE>-<CAT_CODE>-<KEY_SPEC>

Contoh brand_code: RUCIKA, TRILLIUN, MASPION, HCL, EXTRANA, MILLIARD, MU, NODROP, POWER
Contoh cat_code:   PIPA, FITTING, POMPA, KABEL, CHEM, MORTAR

Contoh KEY_SPEC per kategori:
- PIPA: <TYPE>-<MM>MM-<INCH>
- FITTING: <JENIS>-<MM>MM
- POMPA: <TYPE_TEXT>-<OUTLET>
- KABEL: <SIZE>-<CABLETYPE>
- CHEM: <ITEM>-<PACKSIZE><UNIT>
- MORTAR: <JENIS_TEXT>

Nama tampil (items.name) disarankan human-readable:
- PIPA PVC RUCIKA AW 25mm (1") 4m
- FITTING RUCIKA CLEAN OUT (AW) 50mm (2")
- KABEL EXTRANA NYM 2x1,5 (mm2) - harga/meter
- NO DROP WATERPROOFING READY MIX 4 Kg

Deduplication: jika sku_code bentrok (nama berbeda), tambahkan suffix -V2, -V3, dst.
Loop max 5 attempt di ExcelImportService::upsertItem().

C4. MAPPING IMPORT PER SHEET
1) RUCIKA (base_uom=BATANG)
   attributes_json: diameter_mm=mm, diameter_inch=inch, od_mm=OD(mm), spec=SPESIFIKASI, panjang_m=4
   pricing: HARGA(final)/findLastCol; price list = RUCIKA_DEFAULT.

2) RUCIKA FITTING (base_uom=PCS)
   pack_qty=ISI/BOX.
   attributes_json: size_mm=MM, size_inch=inch, jenis=JENIS, isi_per_box=ISI/BOX.
   pricing: parse HARGA/PCS (string rupiah); price list = RUCIKA_DEFAULT.

3) HCL (base_uom=PCS)
   attributes_json: outlet=Outlet, power_watt=Power (parse W), type_text=Type, jenis=Jenis.
   pricing: buat 2 price list: HCL_TEMPO dan HCL_TUNAI.

4) MASPION (base_uom=BATANG)
   attributes_json: type=TYPE, ukuran_inch=UKURAN, panjang_m=4.
   pricing: NETTO; price list = MASPION_DEFAULT.

5) FITTING MASPION (base_uom=PCS)
   pack_qty=Pack.
   attributes_json: jenis=Jenis, class=Class, ukuran_inch=Ukuran, isi_per_box=Pack.
   pricing: kolom Harga; price list = MASPION_DEFAULT.

6) PIPA TRILLIUN (base_uom=BATANG)
   attributes_json: type=TYPE, ukuran_inch=UKURAN.
   pricing: HARGA(final); price list = TRILLIUN_DEFAULT.

7) EXTRANA (base_uom=METER) — PIVOT MATRIX
   Untuk setiap baris ukuran, buat SKU per cable_type yang punya harga > 0.
   attributes_json: cable_size=Ukuran, cable_size_unit=SATUAN, cable_type=<nama kolom>.
   pricing: sell_price = nilai sel per meter; price list = EXTRANA_DEFAULT.

8) MILLIARD (base_uom=ROLL)
   attributes_json: diameter_inch=DIAMETER(INCH), length_per_roll_m=M/ROLL,
                    jenis=JENIS, produk=PRODUK.
   pricing: HARGA(final); price list = MILLIARD_DEFAULT.

9) MU (base_uom=PACK)
   CATATAN: base_uom menggunakan PACK (bukan PCS).
   attributes_json: merk=MERK, produk=PRODUK, jenis=JENIS.
   pricing: NETTO; price list = MU_DEFAULT.
   DISC nominal (contoh 2000) dari Excel hanya di raw_source_json.

10) NO DROP (base_uom=PCS)
    attributes_json: item_name=ITEM, pack_size & pack_size_unit parse dari KEMASAN.
    pricing: NETTO; price list = NODROP_DEFAULT.

11) POWER PRALON (base_uom=BATANG)
    attributes_json: tipe=TIPE, model=MODEL, diameter_inch=Inch, diameter_mm=mm.
    pricing: buat 2 price list: POWER_PRALON_NETT_7_5 dan POWER_PRALON_NETT_18.

C5. VALIDASI SAAT IMPORT (HARUS ADA)
- sku_code dan name tidak boleh kosong → failed jika kosong.
- base_uom wajib valid (findUom() throw firstOrFail jika tidak ada di DB).
- price kosong/null → item dibuat tanpa PriceListItem (tidak ada harga awal).
- pack_qty kosong → default 1.
- Untuk EXTRANA: hanya buat SKU jika price cell numeric dan > 0.

==========================================================================================
E. KETERKAITAN DENGAN MODUL LAIN (AGAR KONSISTEN)
==========================================================================================
1) POS
- POS mencari barang via barcode atau search name/sku_code.
- Saat transaksi disimpan, sistem menyimpan snapshot harga_jual per item (sesuai kebijakan arsitektur).

2) Inventory
- Stok dicatat pada level SKU per cabang/gudang.
- Perubahan master produk tidak mengubah histori stok & transaksi; hanya mempengaruhi transaksi berikutnya.

3) Delivery Order (DO)
- DO mereferensikan SKU dan qty.
- Setelah DO dibuat, item & qty tidak boleh diubah tanpa mekanisme void/regenerate (kebijakan penguncian).

4) Purchasing & AP
- PO/GRN memakai SKU; receiving dapat input dalam unit purchase (BOX/ROLL) lalu konversi ke base_uom via pack_qty.
- Harga beli dapat menggunakan supplier price list (bisa dimulai dari Excel lalu disesuaikan).

 J.1 LIHAT DAFTAR ITEM (INDEX)
═══════════════════════════════════════════════════════════════════════════════

  Request: GET /admin/items[?brand_id=&category_id=&active=&q=]
  Middleware: auth → auth.session → active
  Controller: ItemController::index()

  Flow:
  1. Gate::authorize('viewAny', Item::class)
     → ItemPolicy::viewAny() → user->hasPermission('items.view')
     → Super Admin: bypass; Tidak punya: 403 Forbidden

  2. Query: Item::with(['brand','category','baseUom'])
     Filter opsional (query string):
     - brand_id    : WHERE brand_id = ?
     - category_id : WHERE category_id = ?
     - active      : WHERE is_active = (bool)
     - q           : WHERE name LIKE %? OR sku_code LIKE %?
     Paginate 10, withQueryString()

  3. Build cascading filter map dari items:
     SELECT DISTINCT brand_id, category_id FROM items WHERE NOT NULL
     → brandToCategories[brand_id] → [category_id,...]
     → categoryToBrands[category_id] → [brand_id,...]
     (untuk filter UI yang saling menyesuaikan)

  4. Return view admin.items.index (items, brands, categories, filterMap)

 J.6 IMPORT EXCEL (IMPORT FORM + PROCESS)
═══════════════════════════════════════════════════════════════════════════════

  Request: GET /admin/items/import
  Flow:
  1. Gate::authorize('import', Item::class) → 'items.import'
  2. Return view admin.items.import

  Request: POST /admin/items/import (multipart/form-data)
  Flow:
  1. Gate::authorize('import', Item::class)
  2. Validasi: excel_file required, mimes:xlsx,xls, max:20480 (20 MB)
  3. $request->file('excel_file')->getRealPath()
  4. ExcelImportService::import($path):
     a. SimpleXLSX::parse($filePath)
     b. Loop sheetNames():
        - trim(sheetName) → lookup sheetConfig
        - Skip jika tidak dikenali
        - Call handler method
     c. Setiap handler:
        - getHeaders(rows, headerRow)
        - findCol / findLastCol → deteksi posisi kolom
        - Loop data rows: skip jika kosong / isLikelyHeader
        - Build $attrs (attributes_json)
        - upsertItem()
     d. upsertItem():
        - Validasi: skuCode dan name tidak kosong → failed jika kosong
        - Cek sku_code EXISTS:
            nama sama → skip (skipped++)
            nama beda → suffix -V2 dst (max attempt 5)
        - Item::create() + raw_source_json disimpan
        - Jika price > 0 → upsertPrice()
        - Auditable: action='create' otomatis
     e. upsertPrice():
        - PriceList::firstOrCreate(name, scope=GLOBAL, effective_from=today)
        - PriceListItem::updateOrCreate(price_list_id + item_id)
  5. Redirect importForm + flash import_result
     (created, skipped, failed, errors[])

================================================================================
 O. CATATAN & PERTIMBANGAN ARSITEKTUR
================================================================================

  1. KATALOG SKU BERSIFAT GLOBAL
     Item, Brand, Category, UoM adalah data global — tidak per-cabang.
     Pricing juga global (scope=GLOBAL) untuk saat ini.
     Override harga per cabang (scope=BRANCH) akan digunakan di Module 03+.

  2. BRANCH SYSTEM (BELUM LENGKAP — Module 03+)
     Tabel branches belum dibuat. Model stub Branch.php sudah ada di
     app/Models/Branch.php agar User::branch() tidak throw Class Not Found.
     FK dari users.branch_id ke branches akan ditambahkan saat diperlukan.

  3. FORM ATRIBUT DI UI (MVP vs Rencana)
     Implementasi saat ini: pasangan input attr_keys[]/attr_values[] (key-value
     row form). Controller memproses via ItemController::parseKeyValue().
     Rencana: form otomatis berbasis category_attribute_sets (dynamic form
     per kategori dengan type validation) — belum diimplementasikan di MVP.

  4. IMPORT EXCEL (OPERASIONAL)
     ExcelImportService tidak membutuhkan ext-zip (tidak tersedia di PHP 8.4.12
     pada server). Library shuchkin/simplexlsx adalah pure PHP.
     Import tidak punya preview/dry-run; langsung proses dan tampilkan summary.
     Untuk re-import: baris yang sku_code + nama sama di-skip; nama berbeda
     mendapat suffix -V2 otomatis.

  5. SUPER ADMIN BYPASS
     Super Admin mendapat akses penuh via bypass di User::hasPermission().
     Tidak perlu entry di role_permissions untuk super_admin.

  6. PACK_QTY UNTUK KONVERSI KEMASAN
     items.pack_qty (decimal 12,4) menyimpan berapa base_uom per purchase_uom.
     Contoh: 1 BOX = 36 PCS → pack_qty = 36.
     Digunakan di modul Purchasing/GRN untuk konversi unit beli ke unit stok.

  7. ATTRIBUTE DEFINITIONS (KONTROL ATRIBUT DINAMIS)
