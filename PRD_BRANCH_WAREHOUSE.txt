5.1 Master Cabang (Branch)

Data wajib:
  - branch_code  : string, unique global, uppercase, max 20 char
                   CATATAN: branch stub saat ini punya kolom 'code' bukan
                   'branch_code'. Migration baru HARUS menggunakan 'branch_code'.
                   Branch model fillable akan diupdate (lihat bagian 10).
  - name         : string, required
  - is_active    : boolean, default true

Data opsional:
  - address      : text, nullable
  - phone        : string max 20, nullable
  - timezone     : string, nullable, default 'Asia/Jakarta' (diisi saat create)
  - notes        : text, nullable
  - metadata_json: JSON, nullable (cadangan untuk extensibilitas masa depan)

Aturan bisnis:
  - branch_code tidak bisa diubah setelah dibuat (readonly di form setelah
    create, kecuali super_admin dengan konfirmasi eksplisit).
  - Cabang nonaktif:
    * Tidak bisa dipilih untuk user baru (validasi di StoreUserRequest)
    * Tidak bisa dipakai untuk transaksi/stok baru (di module berikutnya)
    * User yang sudah terikat ke cabang nonaktif: tetap ada, ditampilkan
      warning di user list, akses transaksi dibatasi di module berikutnya
    * Data historis tetap bisa dibaca (audit trail)
  - Tidak ada hard delete; hanya deactivate/reactivate.
  - Saat branch baru dibuat, sistem OTOMATIS membuat 1 warehouse default
    (lihat 5.2 Aturan otomatis).

5.2 Master Gudang per Cabang (Warehouse)

Data wajib:
  - warehouse_code : string, UNIQUE GLOBAL (Opsi A), max 30 char
                     Format auto-generated saat create branch: {BRANCH_CODE}-MAIN
                     Contoh: JKT-MAIN, BDG-MAIN
  - branch_id      : FK → branches.id, required
  - name           : string, required
  - is_active      : boolean, default true

Data opsional:
  - type           : enum (MAIN | SECONDARY | RETURNS), nullable
                     Default MAIN untuk gudang yang dibuat otomatis
  - notes          : text, nullable
  - metadata_json  : JSON, nullable

Aturan bisnis:
  - Setiap cabang minimal memiliki 1 gudang MAIN (dibuat otomatis).
  - Gudang nonaktif tidak bisa dipakai untuk transaksi/stock movement baru
    (enforcement di module Inventory dan POS, bukan di modul ini).
  - Tidak ada hard delete; hanya deactivate/reactivate.

Aturan otomatis pembuatan default warehouse:
  - Trigger: setelah Branch berhasil dibuat (model event 'created' atau
    di BranchController::store() setelah $branch->save()).
  - Data default:
      warehouse_code = "{$branch->branch_code}-MAIN"
      name           = "Gudang Utama"
      type           = "MAIN"
      is_active      = true
      branch_id      = $branch->id

5.5 Audit Log (Append-only, menggunakan infrastruktur existing)

Infrastruktur audit_logs + Auditable trait sudah ada dari Module 01.
Branch dan Warehouse cukup menggunakan trait Auditable — tidak perlu
kode tambahan untuk infrastruktur audit.

Peristiwa yang otomatis tercatat via Auditable trait:
  - create branch     → action: create,         auditable: App\Models\Branch
  - update branch     → action: update,         auditable: App\Models\Branch
  - deactivate branch → action: status_change,  auditable: App\Models\Branch
  - reactivate branch → action: status_change,  auditable: App\Models\Branch
  - create warehouse  → action: create,         auditable: App\Models\Warehouse
  - update warehouse  → action: update,         auditable: App\Models\Warehouse
  - deactivate wh     → action: status_change,  auditable: App\Models\Warehouse
  - reactivate wh     → action: status_change,  auditable: App\Models\Warehouse

Field audit yang sudah ada dan dipakai:
  - user_id (actor)
  - auditable_type (App\Models\Branch atau App\Models\Warehouse)
  - auditable_id
  - action (dari AuditActionEnum)
  - old_values / new_values (JSON snapshot)
  - ip_address, user_agent
  - created_at

Kolom 'password' dan 'remember_token' dikecualikan via $auditExclude.
Untuk Branch dan Warehouse tidak ada kolom sensitif, jadi $auditExclude = [].

6) USER STORIES
──────────────────────────────────────────────────────────────────────────────
Branch:
1) Sebagai Super Admin, saya bisa membuat cabang baru dengan kode unik dan
   nama, dan sistem otomatis membuat gudang MAIN untuk cabang tersebut.
2) Sebagai Super Admin, saya bisa mengedit data cabang (nama, alamat, phone,
   timezone, notes) — branch_code readonly setelah dibuat.
3) Sebagai Super Admin, saya bisa menonaktifkan cabang yang sudah tidak
   beroperasi (dan mereaktifkannya kembali jika diperlukan).
4) Sebagai Owner, saya bisa melihat daftar semua cabang dan statusnya.
5) Sebagai Admin Cabang, saya hanya bisa melihat data cabang saya sendiri
   (beserta gudangnya).

Warehouse:
6) Sebagai Super Admin, saya bisa menambahkan gudang tambahan (SECONDARY/
   RETURNS) pada cabang tertentu.
7) Sebagai Admin Cabang, saya bisa menambah/mengedit/menonaktifkan gudang
   di cabang saya sendiri.
8) Sebagai Kasir dan Accounting, saya bisa melihat daftar gudang cabang saya.
9) Sebagai Owner, saya bisa melihat semua gudang di semua cabang.

Audit:
10) Sebagai Owner/Accounting, saya bisa melihat audit log perubahan
    cabang/gudang (melalui halaman audit log yang sudah ada).

7.1 Branch CRUD

Routes (mengikuti konvensi admin/* yang sudah ada):
  GET    /admin/branches            → index   [branches.view]
  GET    /admin/branches/create     → create  [branches.create]
  POST   /admin/branches            → store   [branches.create]
  GET    /admin/branches/{branch}   → show    [branches.view]
  GET    /admin/branches/{branch}/edit → edit [branches.update]
  PUT    /admin/branches/{branch}   → update  [branches.update]
  PATCH  /admin/branches/{branch}/deactivate → deactivate [branches.deactivate]
  PATCH  /admin/branches/{branch}/reactivate → reactivate [branches.deactivate]

Validasi (StoreBranchRequest):
  - branch_code : required, string, max:20, uppercase, unique:branches,branch_code
                  regex: /^[A-Z0-9_-]+$/
  - name        : required, string, max:100
  - address     : nullable, string, max:500
  - phone       : nullable, string, max:20
  - timezone    : nullable, string, max:50, default 'Asia/Jakarta' jika kosong
  - notes       : nullable, string
  - is_active   : boolean

Validasi (UpdateBranchRequest):
  - branch_code : readonly — tidak terima di request (ignore atau strip)
  - name        : required, string, max:100
  - address     : nullable, string, max:500
  - phone       : nullable, string, max:20
  - timezone    : nullable, string, max:50
  - notes       : nullable, string
  - is_active   : boolean (hanya super_admin, via deactivate route terpisah)

Branch scoping di controller:
  - Global roles (super_admin, owner): tidak ada filter → tampil semua branch.
  - Non-global: query di-scope ke branch_id mereka sendiri → hanya bisa
    GET/show branch mereka sendiri (enforce di BranchPolicy).

7.2 Warehouse CRUD

Routes:
  GET    /admin/warehouses              → index   [warehouses.view]
  GET    /admin/warehouses/create       → create  [warehouses.create]
  POST   /admin/warehouses              → store   [warehouses.create]
  GET    /admin/warehouses/{warehouse}  → show    [warehouses.view]
  GET    /admin/warehouses/{warehouse}/edit → edit [warehouses.update]
  PUT    /admin/warehouses/{warehouse}  → update  [warehouses.update]
  PATCH  /admin/warehouses/{warehouse}/deactivate → deactivate [warehouses.deactivate]
  PATCH  /admin/warehouses/{warehouse}/reactivate → reactivate [warehouses.deactivate]

Validasi (StoreWarehouseRequest):
  - warehouse_code : required, string, max:30, uppercase, unique:warehouses,warehouse_code
                     regex: /^[A-Z0-9_-]+$/
  - branch_id      : required, exists:branches,id,is_active,1
                     (hanya branch aktif bisa dipilih)
                     Untuk non-global user: branch_id HARUS sama dengan
                     user's branch_id (enforce di withValidator atau Policy)
  - name           : required, string, max:100
  - type           : nullable, in:MAIN,SECONDARY,RETURNS
  - notes          : nullable, string
  - is_active      : boolean

Validasi (UpdateWarehouseRequest):
  - warehouse_code : readonly — tidak bisa diubah setelah dibuat
  - branch_id      : readonly — tidak bisa diubah setelah dibuat (gudang
                     tidak bisa dipindah antar cabang)
  - name           : required, string, max:100
  - type           : nullable, in:MAIN,SECONDARY,RETURNS
  - notes          : nullable, string

Warehouse scoping:
  - Gunakan BranchScoped trait yang sudah ada di app/Traits/BranchScoped.php.
  - Warehouse::forBranch($branchId)->get() — null = tidak difilter (global).
  - Policy memastikan non-global user hanya bisa CRUD warehouse cabangnya.

Pola yang sudah ada di User model (TIDAK berubah):

──────────────────────────────────────────────────────────────────────────────
15) KEPUTUSAN ARSITEKTUR YANG TELAH DITETAPKAN
──────────────────────────────────────────────────────────────────────────────

KEP-01: branch_code (bukan 'code')
  Branch stub model punya kolom 'code'. Migration baru pakai 'branch_code'.
  Branch model fillable diupdate ke 'branch_code'. Keputusan final: branch_code.

KEP-02: warehouse_code global unique (Opsi A)
  Menggunakan unique global (bukan unique per branch) untuk menghindari
  duplikasi cross-branch dan memudahkan lookup tanpa perlu branch context.

KEP-03: FK constraint RESTRICT (bukan CASCADE DELETE)
  warehouses.branch_id → RESTRICT: branch tidak bisa dihapus jika masih ada
  warehouse. Tapi kita tidak hard delete branch, jadi ini hanya safety net.
  users.branch_id → NULL ON DELETE (jika branch suatu saat dihapus, user
  tidak ikut terhapus — data historis aman).
  price_lists.branch_id → NULL ON DELETE (sama seperti users).

KEP-04: Auto-create warehouse MAIN di controller (bukan model event)
  Membuat warehouse MAIN di BranchController::store() (bukan di Branch::boot()
  via event 'created') karena:
  - Lebih eksplisit dan mudah ditest
  - Menghindari side effect saat seeder atau test membuat branch langsung
    via model tanpa melalui controller
  - Seeder yang ingin branch tanpa warehouse bisa melakukannya langsung
  Alternatif: jika ingin via model event, gunakan Branch::creating() observer
  yang bisa di-disable via flag saat testing (BranchObserver::$autoWarehouse).

KEP-05: Tidak ada soft delete pada Branch dan Warehouse
  Konsisten dengan Module 02 (brands, categories, uoms, items hanya is_active).
  Alasan: entitas ini tidak punya transaksi yang perlu dilindungi dari deletion
  (itu tugasnya FK RESTRICT), dan audit trail sudah cukup via audit_logs.

KEP-06: accounting role tetap non-global (requiresBranch=true)
  Accounting hanya melihat data cabangnya sendiri. Jika laporan lintas cabang
  diperlukan, tambahkan permission 'reports.view_all' yang sudah ada di existing
  permission set — tanpa mengubah role menjadi global.
